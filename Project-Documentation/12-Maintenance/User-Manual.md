# User manual

The website is Arabic. These English instructions explain current behavior, not a substitute interface.

## Student

1. Browse available universities, courses and services.
2. Create a student account, select the controlled university/faculty options and submit the request. Membership remains pending until review.
3. If identity exists but scope submission failed, log in and complete the account form instead of creating another account.
4. After activation, open eligible academic resources, save courses and manage personal progress. Other universities' protected content remains unavailable.
5. Use teams, volunteering, certificates, voting and service requests only where eligible; follow the status shown in requests/notifications.
6. The Student Center card currently has zero balance. Top-ups and electronic purchases are unavailable. Supported cash/request paths do not imply an electronic debit.

## Coordinator

A Coordinator uses the same student account. Switch mode from profile/settings when that capability is assigned. Student mode remains available; switching does not expand assigned rights. Contact the authorized faculty affairs team for assignment corrections.

## Agent

Log in with the assigned account, wait for activation where pending, and work only in enabled sections. Read/edit/publish may differ. A student-activity assignment cannot gain academic/team powers by navigation. Restaurant profile information is read-only for ordinary agents; platform admin maintains the restaurant-category profile.

## Platform administration

Use institution/agent/student/organization views according to your grant. Text search reaches the database but returns at most 100 matching rows; narrow broad queries. Review activation separately from email verification. Do not change real-user roles/statuses merely to test a screen. Institution disable/delete has related access effects and requires deliberate review.

## Email, later activation

The new verification and recovery screens are implemented but not available in the current disabled configuration. Once activated, new accounts confirm inbox ownership before entering the app, then complete membership scope. Recovery gives a generic message and a time-limited link; resetting a password signs out earlier sessions. Existing pre-cutoff accounts retain login access. Never share verification/reset links.

## Help

Use the in-platform support path where available. No public support inbox or response-time promise is established by this manual. Do not send passwords or private student lists in a public issue.
