# UI screens

Full-page screens of the live Student Hub interface, grouped by role, plus a design system sheet. They are screenshots of the real build, not a redesign. The interface is Arabic-only and right-to-left.

## Folders

| Folder                | Contents                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `00-Design-System/`   | Colors, typography, shape and spacing, buttons, form fields, cards (`Design-System.png` and `.pdf`). |
| `01-Public-Guest/`    | Public and guest pages. 20 screens as PNG, plus one PDF with all of them.                            |
| `02-Student/`         | Student pages. 12 screens as PNG, plus one PDF with all of them.                                     |
| `03-Admin/`           | Platform admin pages. 11 screens as PNG, plus one PDF with all of them.                              |
| `04-Student-Affairs/` | Student affairs agent pages. 12 screens as PNG, plus one PDF with all of them.                       |
| `05-Store-Agent/`     | Store agent pages. 6 screens as PNG, plus one PDF with all of them.                                  |
| `06-Coordinators/`    | Coordinator pages. 10 screens as PNG, plus one PDF with all of them.                                 |

Each role folder holds numbered PNG files (full-page captures) and a combined PDF named after the folder.

## How these were made

- The production build was run locally and each page was opened with Playwright (Chromium) at 1440 px wide, or 390 px for mobile, then captured full page.
- Signed-in screens use disposable local accounts. No production account, data or setting was used or changed.
- The Design System sheet is built from the compiled stylesheet and computed styles of the same build, so it matches the site. It is not exported from Figma.

## Limits

- The data on screen is the local test dataset. It contains test fixtures (for example names like "test student" with generated example.test emails and numbered test store items). It shows layout and components, not real content. Counts on the home page differ from production.
- One screen of each kind is captured. Detail pages other than a course (for example a store item or a request) and other states (empty, error, loading, modal dialogs, forms with validation errors) are not all covered.
- Pages a role cannot open show a "No access" panel. One example per role is kept as `No-Access-State`.
- Some images (for example the restaurant logo in the store agent dashboard) show broken-image icons because the test data has no uploaded files.
- The Figma file was not available, so these screens document the build, not the original Figma frames. The two may differ.
- The Student Affairs Dashboard and Students screens look alike because the dashboard is the student management page.
