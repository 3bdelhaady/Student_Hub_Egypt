# Removable owner-review demos

`review-demo-v1-*` entries and `review-demo-store` / `review-demo-services` are fictional review content, isolated from existing providers. All cards use the `ديمو:` prefix and a persistent `demo` flag. Existing real accounts and grants are untouched. No fake certificates are created.

Eight visible database-backed cards cover product, housing, restaurant, concert ticket, trip ticket, team, volunteer and poll. The ninth historical training card is archived and unpublished. The existing Student Link page-only demo array remains separate. Store transactions are private manual requests, not payments, shipments, issued tickets or external reservations. Team/volunteer acceptance does not create external memberships. Polls persist votes and show aggregates, not individual voter lists.

The seed is insert-once, transactionally claimed as `review-demo-v1-content`. Editing or unpublishing a demo does not cause the next deployment to reset it. DEMO_MODE is still required by the seed. No credentials are stored in source or generated by this seed.

## Test agent

Create a separate new account via admin, assigned only to `review-demo-store`, department private sector, representative, not super. Grant read/edit/publish only to product, housing, restaurant and ticket, then activate that new assignment. All other sections stay denied. Never reassign an existing user to this role. Explicit private-sector section grants also disable legacy generic domain-content editing. Legacy private-sector accounts with null section permissions retain their existing semantics.

## Review

1. As a student, open each `/store?kind=product|housing|restaurant|ticket`, test both `ticketType=concert` and `ticketType=trip` under tickets, find the `ديمو:` card, open it and submit a manual request with fake text. Confirm it appears in `/requests`.
2. In a different browser profile, sign in as the separate store test agent. `/manage` shows exactly four store sections. Open the request, reply and accept/complete it. Student sees status, reply and notification.
3. Student core services: `/services?kind=team`, open the demo and request joining; `/services?kind=volunteer`, select the demo and a division, submit; `/services?kind=poll`, select the demo and vote, reload to see the saved choice. Admin manages these separate service demos. The store agent must not access them.
4. Certificates remain empty until an authorized real record is manually added or imported. Do not fabricate accreditation or student credentials.

## Hide or retire

- Normal UI: admin can unpublish each demo entry and suspend the separate store test agent. Unpublishing is persistent across deploys.
- Operator: `npx tsx scripts/remove-review-demos.ts --confirm-hide-review-demo-v1` against the intended environment unpublishes the isolated demo providers' entries and deactivates those two demo providers. It writes `review-demo-v1-disabled`, preventing seed recreation. It does not delete request histories, votes, accounts or certificates.
- Separately suspend the test agent via admin and remove its vault entry if no longer needed. Keep passwords out of chat.
- Student Link page-only examples are removed by emptying `demoOpportunities` in `src/modules/portal/opportunities.ts`; the old hide control is removed. Students can review and consent to a private manual application to platform admin; there is no external employer submission.
